# M16 live reliability and token-efficiency plan

Updated: 2026-09-04.

## Objective

M16 addresses the failure modes exposed by the third authorized NVIDIA/Kimi K3 comparison without weakening M3 capability authority, M5 independent verification, repository acceptance, or live-evidence boundaries.

## Reliability tranche

The grounded coding provider reduces model-owned state to the fields that actually require model judgment. For M4 planning the model selects a bounded discovered path, complete replacement content, and a registered quality command. Odin rebinds the optimistic SHA and deterministic task metadata from trusted runtime discovery. For repair the model supplies replacement content only; Odin rebinds the persisted path and current SHA.

The compatible-provider parser also tolerates one narrowly defined interoperability shape: an otherwise exact structured JSON response enclosed by one complete Markdown JSON fence. JSON embedded in surrounding prose remains rejected. Schema validation and all downstream authority checks remain unchanged.

## Efficiency hypothesis

The optimized path should reduce token waste by removing package metadata, SHA echoes, task boilerplate, and repair path/SHA repetition from the provider contract and by sizing output ceilings to the target file instead of always using the legacy 3,072 / 2,048 token ceilings. This is a hypothesis until measured live; no percentage is claimed before matched evidence exists.

## Authorized evaluation sequence

1. Normal exact-head PR CI must pass before merge.
2. Merge this reliability tranche to `main`.
3. Authorized live run 4: same provider/model and deterministic fixtures, legacy M4 versus grounded M4. Measure quality, completion, first-pass success, provider calls, latency, input/output/total tokens, and mutation correctness.
4. Review run 4 before any fifth provider run. If a deterministic Odin defect is found, repair, verify, and merge it first.
5. Authorized live run 5: a harder bounded strength probe covering ambiguity, adversarial repository text, API preservation, repair behavior, and noisy-but-irrelevant context. Preserve a separate immutable evidence identity.
6. Kimi K3 remains the primary model. A GLM-5.3 fallback is allowed only if Kimi is unavailable and the exact NVIDIA-hosted model identity is independently verified; no model id is guessed.

## Claim boundary

M16 may report measured Odin uplift only for matched tasks actually executed by the same model/profile. It must not convert system-level safety or orchestration features into unsupported model-intelligence claims. GPT-6 Astra and Claude Fable 5.1 may be shown in a comparison table only with explicit evidence labels; `overtrifft` is reserved for comparable measurements or clearly scoped system properties, never inference from marketing or unrelated benchmarks.
